# config-consumers.txt — the Config Consumption Sweep's permanent ledger (Phase 9.5 CLOSEOUT,
# 2026-07-27). One line per seeded byosmtp.config key (must match config-manifest.txt exactly, in
# any order): a real dial cannot pass config_drift alone — it must ALSO have a genuine consumer
# cited here, or be explicitly marked RESERVED (never both silent AND passing).
#
# Format: key|grep-ERE-pattern-proving-consumption
#     or: key|RESERVED|<expiry-gate-or-phase>
#
# The pattern is checked by tests/harness/checks/config_consumption.sh with:
#   grep -rlE '<pattern>' --include=*.go --include=*.js <repo root> \
#     | grep -vE '_test\.go$|/dispatch/config\.go$|/adminapi/config_validate\.go$'
# i.e. it must appear SOMEWHERE OTHER than the loader (dispatch/config.go), the write-time
# validator (adminapi/config_validate.go), or a test file — a genuine runtime consumer, not just
# "this key is known to exist." RESERVED entries additionally require the literal marker
# "RESERVED / NOT-YET-CONSUMED" to appear in Docs/config-reference.md for that key (checked
# separately) — so a key cannot be silently downgraded to RESERVED without a documented reason an
# operator can actually read.
#
# RESERVED expiry (M3-P2-OD-8, ruled 2026-07-31): the third field is REQUIRED and names the
# gate/phase by which the marker must be gone — checked against Docs/current-phase.txt. A marker
# whose expiry has passed fails the gate, so the hatch cannot quietly become permanent. This is
# why the two rows below carry a phase, not why they're exempt: retry_count_4xx and
# variation_zero_width_rate_pct were both found RESERVED with no expiry by accident during a
# Phase 9.5 review sweep, which is exactly the failure mode this field exists to close.
#
# Maintenance rule (mirrors the ADR-0008 grants-invariant discipline): every new seeded key gets a
# line here in the SAME change that adds the migration — the gate fails a key with no line at all,
# so a key can never silently ship undocumented-as-to-consumption.
