# user-copy-strings.txt — Phase 8 §2.4's ledger of every user-facing string on the audited surfaces
# (From gate, SMTP error framing, notification templates, and — added by the gate's first run — the
# reason text of account events). Mirrors user-output-readers.txt's shape: a checked-in flat file,
# not prose, so a new string cannot be added silently. The gate is BUILT (FW-M3-21):
# services/control/internal/copyledger diffs this file's string_id column against the code's own
# `// copy-ledger: <id>` markers and against the id column of user-facing-copy.md, three-way
# set-equal, failing in every direction (a code site with no row, a row with no code site, a row with
# no audit verdict, a verdict with no row), and fails any prose literal in a file that renders copy
# that carries no marker. Its paired control is tests/harness/checks/user_copy_ledger_selftest.sh.
# What it cannot check, per M3-P8-OD-3: whether the evidence_it_asserts column is TRUE.
#
# Format: one row per line, pipe-delimited, exactly three fields:
#   string_id|surface|evidence_it_asserts
#
# string_id: a stable slug for the string (function/branch name where the string has no ExternalCode
#   of its own). surface: fromgate | smtp_error_frame | notifications | account_events. evidence_it_asserts: the
# SPECIFIC fact the module holds at render time that the string is grounded in — not a paraphrase of
# the string's wording, the underlying evidence. A string whose evidence column would have to say
# "nothing" is the defect this ledger exists to surface.

# --- Surface 2: SMTP error surfacing (services/control/internal/dispatch/verify.go, platformapi report/quote/test paths) ---
# NOTE: the worker's scrubbed provider text (smtp_response) itself is NOT a string in this codebase's
# copy contract — it is verbatim third-party text passed through unmodified (Rule 5's "the provider
# writes this copy, not us"). The rows below are the FRAME text this codebase adds around it.
smtp_frame.verify_connect_failed|smtp_error_frame|worker's ReasonConnectRefused — a real connection-refused result observed on this attempt
smtp_frame.verify_timeout|smtp_error_frame|worker's ReasonTimeout — the server did not answer inside the operation timeout on this attempt
smtp_frame.verify_tls_unavailable|smtp_error_frame|worker's ReasonStartTLSUnavail — STARTTLS was structurally absent from the EHLO response on this attempt; worker aborted before AUTH by construction (Rule 6), so "before sending your password" is a fact about worker behavior, not an inference
smtp_frame.verify_tls_failed|smtp_error_frame|worker's "starttls_failed" — a real TLS negotiation failure observed; "often a certificate problem" is hedged (often, not always) and matches the class's known common cause
smtp_frame.verify_auth_failed|smtp_error_frame|worker's ReasonAuthFailed (AUTH rejected by the server) — the observed fact is that the server rejected AUTH; the frame attributes this to username-or-password without naming which, but does not attribute a DIFFERENT cause (app-password/blocked-sign-in/IMAP-disabled) the same 5xx can also mean
smtp_frame.verify_protocol_error|smtp_error_frame|worker's "ehlo_failed" — the server's EHLO reply did not parse as expected SMTP
smtp_frame.verify_connection_lost|smtp_error_frame|worker's "connection_closed"/"write_failed" or an unrecognized reason slug — the connection dropped mid-handshake; used as the catch-all default too, so an unrecognized slug is asserted only as "connection lost," never invented as a more specific cause
report.smtp_response_passthrough|smtp_error_frame|jobs.last_smtp_response, the worker's own scrubbed provider text for the job's most recent real attempt — surfaced verbatim, no interpretive frame added (report handler adds only the field name, not prose)
report.error_class_passthrough|smtp_error_frame|jobs.last_error_class, the locked send_byo.error_class enum's own text value for the job's most recent real attempt — a structural classification, not prose
account_test.verification_unavailable|smtp_error_frame|s.verifier is nil (no verifier configured) or Verify returned a plumbing error — asserts only that the check could not run, not a credential outcome

# --- Surface 3: notification templates (services/control/internal/dispatch/notify.go, account_effect.go, campaign_expiry.go) ---

# into user-facing text. There is therefore no rendered STRING to audit on this surface yet; the two
# rows below audit the STRUCTURED CLAIM each payload's reason/condition value carries, since that
# value is what a future render would have to stay honest to.
notif.account_quarantined|notifications|newQuarantine transition confirmed by quarantineDecision() against this account's OWN observed data on this outcome: reason='auth_failure' (this specific attempt's AUTH was rejected), 'consecutive_failures' (this account's own streak counter reached the configured threshold), or 'failure_rate' (this account's own windowed attempts/failures ratio crossed the configured rate) — never a claim about any other account or a system-wide condition
notif.campaign_expired|notifications|campaign_expiry_sec elapsed with the campaign's queued jobs not drained by expires_at — an observed elapsed-time fact against this campaign's own rows, re-asserted under the row's own lock at fire time (not a stale read)
