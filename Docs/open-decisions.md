## New this build (Phase 0 execution surfaced these)

| # | Decision | Status | Detail |
|---|---|---|---|
| OD-16 | `make` unavailable on Windows dev host | **APPLIED** | Portable entrypoint is `scripts/dev.sh`; `Makefile` delegates to it. CI (Ubuntu) has `make`; both call the same script, so dev==CI holds. |
| OD-17 | Phase 0 owns a bootstrap migration (schema+roles), which the plan had placed in Phase 1's `sender_0001/0002` | **APPLIED — needs your awareness** | The DONE criteria require Phase 0 to apply + prove schema/roles/grants. Phase 0 ships `sender_0001_bootstrap`. **Phase 1's feature migration chain now begins at `sender_0002`** (enums), not `sender_0001`. If you'd rather Phase 1 own schema creation and Phase 0 only prove the runner against a throwaway migration, say so — but then "apply the empty sender schema + roles/grants and record it" (a DONE criterion) moves to Phase 1. See ADR-0002. |
| OD-18 | Pre-`sender.config` bootstrap values | **APPLIED** | `sender.config` is created in Phase 1 (`sender_0010`). At Phase 0 the Brain reads its few wiring values (singleton timeout, addresses, box id/token hash) from env — the same documented bootstrap-exception class as the runner's `lock_timeout`. No behavioral dial is hardcoded. Phase 1 moves box `token_hash` into `sender.boxes`. |
| OD-19 | Host antivirus TLS-inspection breaks host→localhost mTLS probes | **APPLIED — dev-host artifact, not a module defect** | On the Windows dev host, Norton intercepts TLS on `localhost:8443` and re-signs the Brain's cert with an untrusted root, so a Go/curl mTLS client on the HOST sees "unknown authority". The box↔Brain mTLS is unaffected INSIDE the Docker network. Resolution: the harness probes the mTLS boxlink routes **in-network** (from the box container), which is the correct, real test anyway. CI (Ubuntu, no interception) is unaffected. No code change; documented so a future dev doesn't chase a phantom cert bug. |
